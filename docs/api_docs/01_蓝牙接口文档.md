# 蓝牙接口文档

> **适用平台**: OSAIG 开源 AI 眼镜 (RV1106B)
> **协议栈**: BlueZ 5.66 (BLE GATT)
> **蓝牙名称**: `OSAIG`

---

## 1. 概述

眼镜端通过 BLE GATT Server 与外部 APP（手机/PC）通信。核心实现位于定制的 `btgatt-server`，基于 BlueZ 5.66 的 L2CAP ATT 通道构建自定义 GATT 服务。数据在眼镜内部通过 POSIX 共享内存 + 信号量进行 IPC 转发，由 `ffm_launcher` 等进程消费。

**关键文件：**

| 文件 | 作用 |
|------|------|
| `third_party/bluez-5.66/tools/btgatt-server.c` | BLE GATT Server 核心实现 |
| `src/ffm_launcher/launch.cpp` | 消费 BLE 数据，触发拍照等业务 |
| `src/touchpad_manager/launch.cpp` | 同类 IPC 消费者 |

---

## 2. BLE GATT 服务定义

### 2.1 自定义服务与特征

眼镜端注册了两个自定义 GATT Service：

| 服务 UUID (16-bit) | 特征 UUID (16-bit) | 属性 | 用途 |
|---------------------|---------------------|------|------|
| `0x8103` | `0x8101` | Write | **手机→眼镜**：APP 写入数据 |
| `0x8102` | `0x8100` | Read / Notify / Indicate | **眼镜→手机**：推送数据（如图片） |
| — | `0x2902` | CCCD | Notify/Indicate 的客户端配置描述符 |

### 2.2 UUID 定义（源码）

```c
// third_party/bluez-5.66/tools/btgatt-server.c
#define UPLOAD_SERVICE_UUID         0x8103
#define UPLOAD_CHARACTERISTIC_UUID  0x8101
#define CUSTOM_SERVICE_UUID         0x8102
#define CUSTOM_CHARACTERISTIC_UUID  0x8100
#define CCCD_UUID                   0x2902
```

## 3. 外部 APP → 眼镜（数据写入）

### 3.1 连接流程

1. **扫描**：APP 扫描 BLE 设备，找到广播名为 `OSAIG` 的设备
2. **连接**：建立 BLE 连接
3. **发现服务**：在 GATT 表中找到 Service `0x8103`
4. **写入数据**：对 Characteristic `0x8101` 执行 GATT Write 操作

### 3.2 数据处理流程

```
APP (GATT Write) → btgatt-server (upload_write_cb)
    → 转为 "BLE:" + 十六进制字符串
    → 写入共享内存 /display_shm
    → sem_post(/display_sem)
    → ffm_launcher (sem_wait) 读取并处理
```

### 3.3 写入回调函数

当 APP 向 `0x8101` 写入数据时，`upload_write_cb` 被触发：

```c
// btgatt-server.c - upload_write_cb
static void upload_write_cb(struct gatt_db_attribute *attrib,
              unsigned int id, uint16_t offset,
              const uint8_t *value, size_t len,
              uint8_t opcode, struct bt_att *att, void *user_data)
{
    char hex_message[BUFFER_SIZE];
    int pos = snprintf(hex_message, sizeof(hex_message), "BLE:");

    // 将原始字节转为空格分隔的十六进制字符串
    for (size_t i = 0; i < len && pos < BUFFER_SIZE - 4; i++) {
        pos += snprintf(hex_message + pos, sizeof(hex_message) - pos,
                       "%02X ", value[i]);
    }

    send_to_display(hex_message);  // 写入共享内存
    gatt_db_attribute_write_result(attrib, id, 0);
}
```

### 3.4 IPC 机制

```c
// 共享内存参数
#define SHM_NAME    "/display_shm"
#define SEM_NAME    "/display_sem"
#define BUFFER_SIZE 128

// send_to_display() 将消息写入共享内存并通知消费者
void send_to_display(const char *message) {
    memset(shared_memory, 0, BUFFER_SIZE);
    strncpy((char*)shared_memory, message, BUFFER_SIZE - 1);
    sem_post(semaphore);
}
```

### 3.5 触发拍照示例

APP 发送 `LAUNCH\n` (字节: `4C 41 55 4E 43 48 0A`)，经转换后变为：

```
BLE:4C 41 55 4E 43 48 0A
```

`ffm_launcher` 检测到该前缀后触发拍照：

```cpp
// src/ffm_launcher/launch.cpp
if (strncmp(current_message, "BLE:4C 41 55 4E 43 48 0A", 4) == 0) {
    log_info("Detected BLE trigger signal. Starting capture process.");
    process_capture();
}
```

> **注意**：`strncmp` 的第三个参数为 `4`，实际只比较前缀 `"BLE:"`，因此任何以 `BLE:` 开头的消息都会触发拍照流程。

## 4. 眼镜 → 外部 APP（图片推送）

### 4.1 Notify 订阅

APP 需要对 Service `0x8102` 下的 Characteristic `0x8100` 启用 CCCD 订阅（写入 `0x0001` 启用 Notify）。

### 4.2 图片分包协议

后台线程 `my_worker` 监控 `/tmp/send` 文件，存在时读取 `/tmp/123.jpg` 并通过 Notify 分包推送：

#### 包格式

**头包（文件长度通知）：**

| 字节偏移 | 长度 | 含义 |
|----------|------|------|
| 0 | 1 | 包类型 = `0x00` |
| 1 | 1 | 文件长度 Byte0 (LSB) |
| 2 | 1 | 文件长度 Byte1 |
| 3 | 1 | 文件长度 Byte2 |
| 4 | 1 | 文件长度 Byte3 (MSB) |

**数据包（JPEG 分片）：**

| 字节偏移 | 长度 | 含义 |
|----------|------|------|
| 0 | 1 | 包类型 = `0x01` |
| 1 | 1 | 包序号高字节 |
| 2 | 1 | 包序号低字节 |
| 3~N | 最多 241 字节 | JPEG 数据片段 |

每个数据包最大负载为 `PACK_LEN = 241` 字节。

### 4.3 发送代码

```c
// btgatt-server.c - 图片发送
// 头包：通知文件大小
data[0] = 0x00;
data[1] = (uint8_t)((fileSize & 0x000000ff) >> 0);   // LSB
data[2] = (uint8_t)((fileSize & 0x0000ff00) >> 8);
data[3] = (uint8_t)((fileSize & 0x00ff0000) >> 16);
data[4] = (uint8_t)((fileSize & 0xff000000) >> 24);   // MSB
ble_pic_send_notification(data, 5);

// 数据包：循环发送 JPEG 分片
while (!feof(fr)) {
    data[0] = 0x01;
    data[1] = (uint8_t)((pack_idx & 0xff00) >> 8);    // 包序号高字节
    data[2] = (uint8_t)(pack_idx & 0xff);              // 包序号低字节
    long rlen = fread(data + 3, 1, PACK_LEN, fr);
    ble_pic_send_notification(data, rlen + 3);
    pack_idx++;
}
```

### 4.4 APP 端重组流程

1. 收到 `data[0] == 0x00` 的包，提取文件总长度
2. 收到 `data[0] == 0x01` 的包，按包序号拼接 `data[3:]` 部分
3. 全部接收完成后得到完整 JPEG 文件

## 5. 传输层技术细节

- **协议**：BLE L2CAP 固定信道 ATT (CID 4)
- **套接字类型**：`socket(PF_BLUETOOTH, SOCK_SEQPACKET, BTPROTO_L2CAP)`
- **工作模式**：外设端 (Peripheral) GATT Server
- **MTU**：默认 BLE ATT MTU，数据包按 `PACK_LEN=241` 字节分片
- **无 SPP/RFCOMM**：本项目未使用经典蓝牙串口协议

## 7. 开发注意事项

1. **蓝牙名称**：设备广播名为 `OSAIG`，部分手机（如小米）可能有兼容性问题
2. **共享内存缓冲区**：仅 128 字节，发送数据不宜过长
3. **btgatt-server 独立运行**：不依赖 BlueZ D-Bus GATT API，通过原始 HCI/L2CAP 建链
4. **图片触发**：拍照完成后自动将 JPEG 放到 `/tmp/123.jpg` 并 `touch /tmp/send` 触发推送
5. **拍照结果通知**：拍照完成后会向共享内存写入 `"PhotoCaptured"` 字符串并 `sem_post`
