# 硬件接口与闭源依赖分析

## 1. 概述

眼镜的硬件资源由以下方式管理：

| 硬件 | 管理方 | 是否可绕过 |
|------|--------|-----------|
| **光波导显示** | `display-service`（开源） | ✅ 可以，通过 `ai_display` SDK 直接写共享内存 |
| **蓝牙** | BlueZ 栈 + `bt_service` | ✅ 独立运行，不依赖 ai-core |
| **相机** | `ai-core`（闭源） | ⚠️ SDK 通过 IPC 与 ai-core 通信 |
| **麦克风** | `ai-core`（闭源） | ⚠️ SDK 通过 IPC 与 ai-core 通信 |
| **喇叭** | `ai-core`（闭源） | ⚠️ SDK 通过 IPC 与 ai-core 通信 |
| **GPIO 按键** | `ai-core` GPIO Hub（闭源） | ⚠️ SDK 通过共享内存/socket 与 ai-core 通信 |

## 2. 各硬件接口详情

### 2.1 光波导显示 — 完全开源可控

**架构**：
```
你的程序 → ai_display SDK → 共享内存 ai_display_shm → display-service → SPI → JBD013
```

**关键参数**：
- 分辨率：640 × 480
- 色深：4bpp 灰度（16 级）
- 帧大小：`AI_DISPLAY_FRAME_SIZE` = 153600 bytes
- 共享内存：`/dev/shm/ai_display_shm`（524KB）
- IPC：Unix Domain Socket

**SDK API**（`ai_display.h`）：
```c
ai_display_client_t* ai_display_connect(void);
uint8_t* ai_display_get_framebuffer(ai_display_client_t *client);
int ai_display_commit(ai_display_client_t *client);
void ai_display_disconnect(ai_display_client_t *client);
```

**依赖**：仅依赖 `display-service`（开源），不依赖 `ai-core`。

**源码位置**：
- 服务端：`src/display-service/main.c`, `hal_driver.c`, `jbd013_api.c`
- 客户端 SDK：`SDK/ai_glass_sdk/include/ai_display.h`
- 示例：`src/launcher-app/main.c`

---

### 2.2 蓝牙 — 独立于 ai-core

**架构**：
```
bt_service (设备名/GATT/RFCOMM)
  ↕ D-Bus
bluetoothd (配对/连接)
  ↕ HCI
rk_hciattach (UART ↔ 蓝牙芯片)
```

**与 ai-core 的关系**：完全无关。蓝牙栈由 S52_bluetooth 独立启动。

**可用接口**：
1. **RFCOMM**（经典蓝牙串口）：`bt_service` 已注册 RFCOMM channel
2. **BLE GATT**：`bt_service` 管理 GATT 服务，写入共享内存 `/display_shm`
3. **直接 socket 编程**：可直接创建 RFCOMM socket（需包含 bluetooth 头文件）

---

### 2.3 相机 — 依赖 ai-core

**SDK API**（`ai_camera.h`）：
```c
// 通过 IPC 与 ai-core 通信
ai_camera_client_t* ai_camera_create(void);
int ai_camera_capture(ai_camera_client_t *client, ...);
```

**底层硬件**：
- 设备节点：`/dev/video*`
- ISP：`/proc/rkisp-vir0`
- 驱动：`video_rkisp.ko`, `video_rkcif.ko`

**绕过可能性**：理论上可以直接用 V4L2 API 操作 `/dev/video*`，但需要：
- 手动配置 ISP（Rockchip ISP 配置复杂）
- 加载 IQ 文件（`/oem/usr/share/iqfiles/`）
- 使用 `rkaiq_3A_server` 处理自动曝光/对焦/白平衡
- 参考 `rkipc` 和 `sample_demo_vi_venc` 等测试程序

---

### 2.4 麦克风 — 依赖 ai-core

**SDK API**（`ai_audio.h`）：
```c
// 通过 Unix Socket 与 ai-core 通信
// ai-core 负责 ALSA 设备管理和音频处理
```

**底层硬件**：
- ALSA 设备：`hw:0,0`
- 驱动：`snd-soc-rv1106.ko`

**绕过可能性**：可以直接用 ALSA API（`rk_mpi_ai_test` 测试工具可以直接采集）：
```bash
# 设备上已有的测试工具
rk_mpi_ai_test        # 麦克风采集测试
rk_mpi_ao_test        # 喇叭播放测试
sample_ai_aenc        # 采集+编码
```

---

### 2.5 喇叭 — 依赖 ai-core

**底层硬件**：
- ALSA 设备：`hw:0,0`
- PA 控制 GPIO：`gpio-33`（pa-ctl，out hi = 开启）

**绕过方式**：直接用 Rockchip MPI 或 ALSA：
```bash
# 播放 PCM 文件（设备上已有工具）
rk_mpi_ao_test -i test.wav --sound_card_name=hw:0,0 --device_ch=2 --device_rate=8000 --set_volume 50
```

---

### 2.6 GPIO 按键 — 依赖 ai-core

**硬件**：
| GPIO | 功能 |
|------|------|
| GPIO 0 | 翻页键 |
| GPIO 1 | 功能键 |
| GPIO 75 | 确认键 |

**SDK 架构**：`ai-core` 运行 GPIO Hub，客户端通过共享内存 `/dev/shm/ai_gpio_event_hub` 订阅事件。

**绕过方式**：直接读取 sysfs：
```bash
# 导出 GPIO
echo 75 > /sys/class/gpio/export
echo in > /sys/class/gpio/gpio75/direction
cat /sys/class/gpio/gpio75/value
```

或使用 poll 方式监听中断：
```c
// 参考 src/touchpad_manager/launch.cpp 的 sysfs 轮询实现
int fd = open("/sys/class/gpio/gpio75/value", O_RDONLY);
struct pollfd pfd = { .fd = fd, .events = POLLPRI };
poll(&pfd, 1, -1);  // 等待 GPIO 变化
```

## 3. 自主开发建议

### 3.1 最简方案：保留 ai-core，只替换 launcher-app

**优点**：工作量最小，所有硬件即可用
**做法**：编写新程序链接 `libai_glass_sdk.a`，替换 `launcher-app`

### 3.2 中等方案：保留 ai-core，自定义程序独立运行

**做法**：自定义程序与 launcher-app 并行运行，通过 SDK IPC 调用各硬件

### 3.3 完全自主方案：不用 ai-core

**工作量大**，需要：
1. **显示**：直接用 `ai_display` SDK（不需要 ai-core）✅
2. **蓝牙**：直接用 BlueZ/socket 编程（不需要 ai-core）✅
3. **相机**：需自己实现 V4L2 + Rockchip ISP 初始化
4. **音频**：需自己实现 ALSA 录音/播放（可参考 `rk_mpi_ai_test` / `rk_mpi_ao_test`）
5. **GPIO**：需自己实现 sysfs 轮询（参考 `touchpad_manager`）
6. **PA 功放**：需手动控制 `gpio-33`

**参考程序**（设备上 `/oem/usr/bin/` 已有）：
- `rk_mpi_ai_test` — 麦克风直接采集
- `rk_mpi_ao_test` — 喇叭直接播放
- `rk_gpio_test` — GPIO 直接读写
- `sample_demo_vi_venc` — 相机采集+编码
- `rkisp_demo` — ISP 演示
