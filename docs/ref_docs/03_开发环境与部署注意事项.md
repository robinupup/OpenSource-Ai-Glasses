## 2. 部署到设备

### 2.1 推送二进制

```bash
adb push build/your_app /oem/usr/bin/your_app
adb shell chmod +x /oem/usr/bin/your_app
```

### 2.2 ★ 推送脚本时的 CRLF 陷阱

**绝对不要**直接从 WSL `adb push` shell 脚本到设备。

**正确方式**：在设备上直接写入：
```bash
adb shell 'cat > /etc/init.d/S60_app_launcher << "EOF"
#!/bin/sh
# 脚本内容...
EOF
chmod +x /etc/init.d/S60_app_launcher'
```

**如果必须 push**，推送后修复：
```bash
adb push my_script /etc/init.d/S60_app_launcher
adb shell "tr -d '\r' < /etc/init.d/S60_app_launcher > /tmp/f && mv /tmp/f /etc/init.d/S60_app_launcher && chmod +x /etc/init.d/S60_app_launcher"
```

### 2.3 修改 init 脚本的安全流程

```bash
# 1. 先备份
adb shell "mkdir -p /userdata/init_backup && cp /etc/init.d/S60_app_launcher /userdata/init_backup/"

# 2. 在设备上直接写入新脚本（避免 CRLF）
adb shell 'cat > /etc/init.d/S60_app_launcher << "EOF"
#!/bin/sh
# 新脚本内容
EOF
chmod +x /etc/init.d/S60_app_launcher'

# 3. 验证换行符
adb shell "hexdump -C /etc/init.d/S60_app_launcher | head -2"

# 4. 手动测试执行
adb shell "sh -x /etc/init.d/S60_app_launcher start 2>&1"

# 5. 物理断电重启验证
```

## 3. 重启相关

### 3.1 软重启 vs 物理断电

| 方式 | 命令 | 蓝牙芯片 | 适用场景 |
|------|------|---------|---------|
| 软重启 | `adb reboot` | **不复位** | 普通应用层修改 |
| 物理断电 | 手动断电再上电 | **完全复位** | 蓝牙异常后恢复 |

### 3.2 何时必须物理断电

- `rk_hciattach` 报 "bt is not in maskrom"
- 手动 kill 过蓝牙相关进程后
- 蓝牙芯片状态异常，`hci0` 无法创建

### 3.3 何时软重启即可

- 只修改了 S60_app_launcher（替换应用程序）
- 只修改了 S53_guard
- 没有动过蓝牙相关进程

## 4. 文件系统说明

### 4.1 分区和持久性

| 路径 | 分区 | 可写 | 重启持久 |
|------|------|------|---------|
| `/etc/init.d/` | rootfs | ✅ | ✅ |
| `/oem/usr/bin/` | oem | ✅ | ✅ |
| `/userdata/` | userdata | ✅ | ✅ |
| `/tmp/` | tmpfs | ✅ | ❌ |
| `/run/` | 可能非 tmpfs | ✅ | ⚠️ 不确定 |

### 4.2 关键目录

```
/oem/usr/bin/          # 应用程序二进制
/oem/usr/lib/          # 共享库
/oem/usr/ko/           # 内核模块
/oem/usr/share/        # ISP 配置、音频资源
/userdata/             # 用户数据（WiFi/BT 配置、固件）
/userdata/rx96x/fw/    # 蓝牙固件
/etc/init.d/           # 启动脚本
```

## 5. 调试技巧

### 5.1 BusyBox 限制

设备使用 BusyBox，以下常用命令**不可用**：
- `pidof` → 用 `ps | grep -v grep | grep xxx`
- `strace` → 不可用
- `fuser` → 不可用
- `timeout` → 不可用
- `ps -o pid,ppid,comm` → 用 `awk` 解析 `/proc/$pid/stat`
- `rfkill` → 不可用

### 5.2 进程检查替代方案

```bash
# 代替 pidof
ps | grep -v grep | grep -q "process_name" && echo "running" || echo "stopped"

# 获取进程的父进程
pid=123
ppid=$(awk '{print $4}' /proc/$pid/stat 2>/dev/null)
cat /proc/$ppid/comm 2>/dev/null
```

### 5.3 内核日志

```bash
# 蓝牙相关
dmesg | grep -iE 'bluetooth|hci|rfkill|rk96'

# GPIO 相关
cat /sys/kernel/debug/gpio

# 音频相关
cat /proc/asound/cards
```
