# 眼镜系统启动与蓝牙排障手册

## 1. 系统启动流程

### 1.1 Init 脚本执行顺序

```
/etc/init.d/rcS 按文件名排序依次同步执行：

S10udev          → 设备管理器
S20linkmount     → 分区挂载
S20urandom       → 随机数初始化
S21appinit       → RkLunch.sh（nginx/fcgiwrap + 内核模块加载）
S50_gpio_setup   → GPIO 初始化
S50usbdevice     → USB 设备
S51_wifi         → WiFi 模块加载（rk96x.ko）
S52_bluetooth    → 蓝牙全栈初始化
S53_guard        → guard → ai-core（相机/麦克风/喇叭/GPIO）
S60_app_launcher → display-service + launcher-app
S99_auto_reboot  → 看门狗
```

**关键特性**：脚本按顺序同步执行，前一个执行完才执行下一个。后台进程用 `&` 启动。

### 1.2 S21appinit → RkLunch.sh 职责

- 执行 `/oem/usr/etc/init.d/S50nginx` 和 `S50fcgiwrap`
- `post_chk &`（后台）：等待 userdata 挂载 → 加载内核模块（`insmod_ko.sh`）→ 网络初始化 → rkipc
- `insmod_ko.sh` 末尾调用 `insmod_wifi.sh &` 加载 WiFi 驱动

### 1.3 S52_bluetooth 蓝牙启动链

```
dbus-daemon                     # D-Bus 系统总线
  → rk_hciattach &              # UART 固件加载，创建 hci0（常驻）
  → sleep 1
  → hciconfig hci0 up           # 启用适配器
  → bluetoothd -n &             # BlueZ 配对/连接管理
  → bluealsa &                  # 蓝牙音频桥接（A2DP/HFP）
  → bluealsa-aplay &            # 蓝牙音频自动播放
  → bt_service BT &             # 设备名 OSAIG、BLE GATT、RFCOMM
```

### 1.4 S60_app_launcher 启动逻辑

- 先等待 `guard` 和 `ai-core` 就绪（最多 30 秒超时）
- 再启动 `display-service`（SPI 推屏守护进程）
- 最后启动 `launcher-app`（LVGL UI 渲染）

## 2. 蓝牙进程功能说明

| 进程 | 功能 | 必要性 |
|------|------|--------|
| `rk_hciattach` | UART 加载蓝牙固件，创建 hci0 设备 | **最底层，必须最先启动** |
| `dbus-daemon` | D-Bus 系统总线，bluetoothd 和 bt_service 依赖 | **基础设施** |
| `bluetoothd` | BlueZ 核心：配对、连接、SDP 服务发现 | **核心** |
| `bt_service` | 设备名 OSAIG、BLE GATT、RFCOMM、设备类配置 | **关键，没它搜不到 OSAIG** |
| `bluealsa` | A2DP/HFP 蓝牙音频桥接到 ALSA | 仅蓝牙音频需要 |
| `bluealsa-aplay` | 自动将蓝牙音频送到喇叭 | 仅蓝牙音频播放需要 |

### 蓝牙配置

```
设备名: OSAIG
地址: 22:22:9A:69:F7:44
配置文件: /userdata/bt_user.conf + /userdata/main.conf
固件路径: /userdata/rx96x/fw/rk96x_bt_loader.bin
Class: 0x240414 (Audio/Loudspeaker)
模式: dual (Classic + BLE)
```

## 3. 关键 Bug 与解决方案

### 3.1 ★ 蓝牙芯片 "bt is not in maskrom" — 最常见问题

**症状**：
```
TAG:hciattach_rk:bt is not in maskrom
```
`rk_hciattach` 立即退出，`hci0` 设备不存在，所有蓝牙服务失效。

**根因**：RK96x WiFi/BT combo 芯片的蓝牙部分需要在 maskrom（固件加载模式）下才能被 `rk_hciattach` 初始化。`adb reboot` 是软重启，**不会切断芯片供电**，蓝牙芯片保持异常状态。

**触发条件**：
- 手动 `killall rk_hciattach` 后尝试重新启动
- 多次调试修改蓝牙相关进程后软重启

**解决方案**：
```
必须物理断电重启（取下充电线/电池，彻底断电后重新上电）
adb reboot 无效！
```

**预防措施**：
- 避免随意 kill `rk_hciattach`，它是常驻进程
- 如果需要调试蓝牙，在修改完成后做一次物理断电重启

---

### 3.2 ★ dbus-daemon PID 文件残留

**症状**：
```
dbus-daemon: Failed to start message bus: The pid file "/run/messagebus.pid" exists
```
`bluetoothd` 随后报 "Unable to get on D-Bus"，蓝牙栈全部失败。

**根因**：`/run/messagebus.pid` 在重启后没被清理。嵌入式系统的 `/run` 可能不是 tmpfs。

**解决方案**：在 S52_bluetooth 的 `mkdir -p /var/run/dbus/` 后加一行：
```bash
rm -f /run/messagebus.pid
```

---

### 3.3 ★ bluetoothd 内置错误的 D-Bus socket 路径

**症状**：
```
D-Bus setup failed: Failed to connect to socket /home/xjy/Downloads/bluez-5.66/bluez_output/var/run/dbus/system_bus_socket
```

**根因**：`bluetoothd` 编译时硬编码了开发者机器上的路径。

**解决方案**：必须设置环境变量覆盖：
```bash
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/var/run/dbus/system_bus_socket'
```
S52_bluetooth 脚本中已包含此设置。如果在 adb shell 中手动启动 bluetoothd，**必须先 export 此变量**。

---

### 3.4 ★ RK96X_TARGET_PATH 缺失

**症状**：
```
TAG:hciattach_rk:RK96X_TARGET_PATH is NULL
```
`rk_hciattach` 找不到蓝牙固件。

**解决方案**：
```bash
export RK96X_TARGET_PATH=/userdata/rx96x
```
S52_bluetooth 脚本第一行就设置了此变量。手动运行时务必先 export。

---

### 3.5 ★ adb push 文件的 CRLF 换行符问题

**症状**：Init 脚本执行时报各种莫名错误：
```
/etc/init.d/S52_bluetooth: line 2: : not found
sh: invalid number '1'
syntax error: unexpected end of file (expecting "then")
```

**根因**：WSL/Windows 环境下的文件包含 `\r\n` (CRLF) 换行符，`adb push` 原样传输，BusyBox `sh` 无法解析 `\r`。

**诊断**：
```bash
hexdump -C /etc/init.d/S52_bluetooth | head -3
# 如果看到 0d 0a 就是 CRLF 问题
```

**解决方案**（在设备上修复）：
```bash
tr -d '\r' < /etc/init.d/S52_bluetooth > /tmp/fix && mv /tmp/fix /etc/init.d/S52_bluetooth && chmod +x /etc/init.d/S52_bluetooth
```

**批量修复所有 init 脚本**：
```bash
for f in /etc/init.d/S*; do
    tr -d '\r' < "$f" > /tmp/fix_tmp && mv /tmp/fix_tmp "$f" && chmod +x "$f"
done
```

**预防**：优先在设备上用 `cat > file << "EOF"` 方式写入脚本，避免从 WSL 推送。

---

### 3.6 修改 init 脚本后服务未生效

**症状**：修改了 S52_bluetooth 等脚本内容，但重启后对应服务没有按预期运行。

**排查步骤**：
1. 确认文件确实被修改：`cat /etc/init.d/S52_bluetooth`
2. 检查换行符：`hexdump -C /etc/init.d/S52_bluetooth | head -3`
3. 手动执行看错误：`sh -x /etc/init.d/S52_bluetooth start 2>&1`
4. 确认文件系统持久化：某些修改可能因为 rootfs overlay 在重启后丢失

## 4. 应用层架构

### 4.1 进程依赖关系

```
guard (闭源守护进程)
  └→ ai-core (闭源核心服务: 相机/麦克风/喇叭/GPIO)

display-service (开源: SPI推屏)
  └→ launcher-app (开源: LVGL UI渲染) 或自定义程序

蓝牙栈 (独立运行，不依赖 ai-core)
  rk_hciattach → dbus → bluetoothd → bt_service
```

### 4.2 显示链路

```
客户端程序 (LVGL/自定义渲染)
  │ 写入像素帧 (4bpp, 640×480)
  ▼
共享内存 /dev/shm/ai_display_shm (524KB)
  │ Unix Socket 通知
  ▼
display-service (读帧 → SPI 传输)
  │
  ▼
JBD013 Micro-OLED → 光波导 → 用户眼睛
```

### 4.3 开源/闭源组件对照

| 组件 | 类型 | 源码位置 |
|------|------|---------|
| `ai-core` | **闭源** | 仅二进制: `Applications/ai-core` |
| `guard` | **闭源** | 仅二进制: `Applications/guard` |
| `display-service` | **开源** | `src/display-service/` |
| `launcher-app` | **开源** | `src/launcher-app/` |
| `ai_glass_sdk` | **开源** | `SDK/ai_glass_sdk/` |
| `bt_service` | 闭源 | 仅二进制: `/oem/usr/bin/bt_service` |

### 4.4 替换 launcher-app 的正确方法

```bash
# 1. 编译你的程序（链接 libai_glass_sdk.a）
make -C src/your_app/

# 2. 部署到设备
adb push build/your_app /oem/usr/bin/your_app
adb shell chmod +x /oem/usr/bin/your_app

# 3. 修改 S60_app_launcher（在设备上直接编辑避免 CRLF）
adb shell 'cat > /etc/init.d/S60_app_launcher << "EOF"
#!/bin/sh
export LD_LIBRARY_PATH=/oem/usr/lib:$LD_LIBRARY_PATH
TIMEOUT=30
while [ $TIMEOUT -gt 0 ]; do
    if ps | grep -v grep | grep -q guard && ps | grep -v grep | grep -q ai-core; then
        break
    fi
    sleep 1
    TIMEOUT=$((TIMEOUT-1))
done
/oem/usr/bin/display-service &
sleep 2
/oem/usr/bin/your_app &
EOF
chmod +x /etc/init.d/S60_app_launcher'

# 4. 物理断电重启
```

**关键要点**：
- 必须保留 `display-service`（你的程序通过 `ai_display` SDK 写入共享内存，`display-service` 负责推屏）
- 必须保留 `guard/ai-core`（相机、麦克风、喇叭依赖它）
- 必须保留蓝牙栈（S52_bluetooth 不要动）
- 修改完成后做物理断电重启

## 5. 常用调试命令

```bash
# 查看蓝牙状态
hciconfig hci0
hciconfig hci0 name

# 查看所有应用进程
ps | grep -vE '\[|grep' | grep -E 'bt_service|hciattach|bluetoothd|bluealsa|guard|ai-core|display-service|launcher-app|nginx|dbus'

# 查看 RFCOMM 连接
cat /proc/net/rfcomm

# 检查脚本换行符
hexdump -C /etc/init.d/S52_bluetooth | head -3

# 调试模式运行 init 脚本
sh -x /etc/init.d/S52_bluetooth start 2>&1

# 手动启动蓝牙（需先 export 环境变量）
export RK96X_TARGET_PATH=/userdata/rx96x
export DBUS_SYSTEM_BUS_ADDRESS='unix:path=/var/run/dbus/system_bus_socket'
export LD_LIBRARY_PATH=/oem/usr/lib:$LD_LIBRARY_PATH

# 查看内核蓝牙日志
dmesg | grep -iE 'bluetooth|hci|rfkill|rk96'

# 恢复原始启动脚本（需要项目源码）
adb push project/oem/init.d/S52_bluetooth /etc/init.d/S52_bluetooth
adb shell "tr -d '\r' < /etc/init.d/S52_bluetooth > /tmp/f && mv /tmp/f /etc/init.d/S52_bluetooth && chmod +x /etc/init.d/S52_bluetooth"
```

## 6. 原始脚本源码位置（用于恢复）

| 设备路径 | 项目源码位置 |
|---------|------------|
| `/etc/init.d/S52_bluetooth` | `project/oem/init.d/S52_bluetooth` |
| `/etc/init.d/S53_guard` | `project/oem/init.d/S53_guard` |
| `/etc/init.d/S60_app_launcher` | `project/oem/init.d/S60_app_launcher` |
| `/etc/init.d/S51_wifi` | `project/app/wifi/S51_wifi` |
| `/oem/usr/bin/RkLunch.sh` | 设备上 `/oem/usr/bin/RkLunch.sh`（直接恢复） |

**完整恢复流程**：
```bash
# 推送原始脚本
adb push project/oem/init.d/S52_bluetooth /etc/init.d/
adb push project/oem/init.d/S53_guard /etc/init.d/
adb push project/oem/init.d/S60_app_launcher /etc/init.d/

# 修复 CRLF
adb shell 'for f in /etc/init.d/S*; do tr -d "\r" < "$f" > /tmp/fix && mv /tmp/fix "$f" && chmod +x "$f"; done'

# 物理断电重启
```
